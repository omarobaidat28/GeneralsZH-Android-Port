# Development Diary - November 2026

---

## 11/11/2026 -- The launcher recognises a game by its files (PLAN-031 step 1)

Request: a PojavLauncher-style app that runs old games from their copied files. The owner chose
one native engine per game behind one launcher (what this app already is for Generals and Zero
Hour) over a Wine + Box64 layer for every Windows game.

New `GameCatalog.java` lists every game the launcher knows: the files that identify its folder
(matched in any case, since copies come from Windows) and, for a game that runs today, its engine
libraries. Zero Hour and Generals run; Renegade, Red Alert and Tiberian Dawn are recognised with
an engine planned (EA released their source under the GPL); Tiberian Sun, Red Alert 2 and Yuri's
Revenge are recognised only, as no source exists to port. `getSelectedGame`, `setSelectedGame`
and `engineLibraries` now read the catalog; the stored ids are unchanged, so installs keep their
game and folders.

Picking a game folder now identifies it first (the folder or the only game folder up to three
levels below). The other runnable game -> a dialog offers to switch to it, or keep the selected one
(the old checks then run as before). A recognised game without an engine -> a dialog names it and
its plan, and nothing is saved. Home shows one line on this and the recognised-only games.

Nine new launcher strings in all thirteen locales. Not compiled here (this machine has no JDK or
Android SDK) and not tried on a device; it needs a launcher build and three picks to verify:
a Generals folder with Zero Hour selected, a Zero Hour folder with Generals selected, and a Red
Alert folder. Engines for the planned games are steps 2-3 of PLAN-031, each a separate port.

Unrelated, seen while checking locales: `online_blocked_by_device_gate`,
`setup_online_blocked_title` and the six `tools_import_map_*` strings exist only in `values/`, so
the other twelve locales fall back to English for them. Predates this change.
